- 验证: env3.8 下基准工况与 GUI 工况均通过，OUT_PY.DAT 与 HP.EXE 参考值偏差与既有标定残差一致（≤2.6%）。GUI/依赖导入正常。

## SO2/CO 组分测试数据报错修复（第二层 6.4.3 限制）
- 新测试数据（dist/测试数据/INB.dat，GUI 手填：热侧 9520000 Nm3/h 213→134.6C，冷侧 618200 Nm3/h 50→170C，CO 23.8%+SO2 0.3%）触发两类新错：
  1. "Could not match the binary pair [7446-09-5,7727-37-9]"：6.4.3 无 SO2-N2/H2/CO/H2O 二元对；且 add_simple_mixing_rule 会把懒加载的二元对库"钉死"（须先创建一次普通混合物触发加载再补规则）。
  2. "Viscosity/Thermal conductivity model is not available"：6.4.3 连 CO、SO2 纯组分输运数据都没有（6.6.0 才补入），H2 可用。
- 修复（hp_thermal.py）：_make_abstract_state 自动补 linear 规则（先触发懒加载）；_mix_mu_kl 用 Wilke + WMS 混合规则回退；_MU_KL_CORR 为 CO/SO2 补 Sutherland 粘度+线性导热关联式（273~650K ±3%）。
- 验证：GUI 手填工况收敛（校核 136x31，U=19.7，冷侧出口 201.6C）；基准 INB.DAT 工况结果不变（749.18）；GUI 依赖正常。

## T=8.2e7K 发散报错修复（第三层：输入解析列错位 + 迭代防护）
- 测试数据（5000/325/200，4700/20/90，KT=1 IBH=9 IMH=10）报 "solver_rho_Tp ... T=8.24e7"。
- 根因1（主因）：该 INB.dat 第12行未按 Fortran 固定列宽书写（数字整体偏移1列），固定列宽解析把 ryh/ryc 切成 0.0003/50.0（应为 0.00035/0），ryc=50 使 U→1/50、所需面积爆炸、校核迭代把 TFCH 推飞。
- 根因2（暴露面）：校核迭代 DAHH 巨大时 TFCH 越界无防护，以 CoolProp 内部报错形式崩溃。
- 修复（hp_thermal.py）：
  1. parse_line 增加自由格式回退：按空白切分恰好得到字段数且全为合法数字时优先采用（列对齐文件结果不变）。
  2. 防护三处：fprop 温度硬上限 [50,2500]K；stage25 热平衡迭代上限 500 次（注：暂态越过 TFJH 是原算法行为，外层 label-800 会拉回，不能按区间限制）；校核面积迭代上限 100 次且要求 TFJC<TFCH<TFJH，超限抛中文原因（含面积偏差%）。
- 关键教训：热平衡迭代暂态可大幅越过 TFJH（大工况收敛路径 tfcc 瞬时到 ~1100℃），防护只能限次数不能限区间。
- 验证：本工况收敛（TFCH=198.93/TFCC=150.52/U=16.03/9x10管）；基准 749.18 不变；大工况 201.55 不变；ryc=50 坏数据给出中文提示（偏差 19892%）。

## GUI 输入控件改为 QLineEdit（笔记本小屏适配）
- 问题: 笔记本上 QDoubleSpinBox/QSpinBox 被压缩得只剩上下箭头（截图），无法看到/输入数值。
- 修改（hp_gui.py）: 全部数值输入控件（28 个参数框 + 7 组分编号 + 14 组分% + IBH/IMH，共 51 个）改为 QLineEdit + QRegExpValidator（RE_FLOAT=[0-9]*\.?[0-9]*，RE_INT=[0-9]*），右对齐，宽度不变。
- collect_params() 统一用 _ed_val() 解析，空/非法文本抛带字段名的中文 ValueError，start_calc 弹窗提示；set_params 按 SPEC 小数位格式化回填。
- 注意: QLineEdit.setText 绕过 validator（Qt 行为），程序内部写入均为格式化数字无影响；validator 只拦用户键入。
- 验证（env3.8 offscreen）: validator 拦截 a/- 正确；载入 INB.DAT→collect→compute 全链路 OK（749.18 基准不变）。
